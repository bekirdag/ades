Your first useful extraction

This example was checked against the hosted service. NVIDIA resolves to the US ticker NVDA with the finance-us-en library.

Terminal 
curl --fail-with-body -sS https://api.adestool.com/v0/tag \
  -H 'Content-Type: application/json' \
  -d '{"text":"NVIDIA reported quarterly earnings.","pack":"finance-us-en"}'
Expected fields · abbreviated actual response
{
  "pack": "finance-us-en",
  "entities": [{
    "text": "NVIDIA", "label": "ticker", "start": 0, "end": 6,
    "link": {
      "entity_id": "finance-us-ticker:NVDA",
      "canonical_text": "NVDA",
      "provider": "lookup.alias.exact"
    }
  }],
  "topics": [{"label": "finance", "evidence_count": 1}]
}

This display omits additional response fields. Scores, versions and timing can change between releases. Compare identity and evidence, not exact timing.

Install & run locally

The Python distribution is ades-tool. The npm distribution is a command-line wrapper that bootstraps a user-local Python environment; it is not a JavaScript tagging SDK.

Python installation 
python3 -m venv .venv
. .venv/bin/activate
python -m pip install ades-tool
ades --version
ades pull finance-us-en
ades tag "NVIDIA reported quarterly earnings." --pack finance-us-en
ades serve
Alternative: npm wrapper 
npm install -g @bekirdag/ades
ades --version
ades pull finance-us-en
ades tag "NVIDIA reported quarterly earnings." --pack finance-us-en

Local results depend on the installed package and library versions. Pull the libraries you need; dependencies are pulled automatically. Check ades serve --help for binding options before exposing a local service.

Call the hosted API from Python

No ADES package is needed for an HTTP client. This example uses Python's standard library.

Python 
import json
from urllib.request import Request, urlopen

request = Request(
    "https://api.adestool.com/v0/tag",
    data=json.dumps({
        "text": "NVIDIA reported quarterly earnings.",
        "pack": "finance-us-en"
    }).encode(),
    headers={
        "Content-Type": "application/json",
        "User-Agent": "ades-docs-example/1.0"
    },
)
with urlopen(request, timeout=30) as response:
    result = json.load(response)
for entity in result["entities"]:
    print(entity["text"], entity.get("link"))

Choose your libraries

A pack defines a domain's available vocabulary and matching data. A country-specific finance pack and a language pack answer different questions: finance-de-en contains Germany-focused finance vocabulary in English, rather than promising German-language extraction.

Finance domainfinance-enDomain coverage; company aliases may be absent
US market names and tickersfinance-us-enIssuer / security identity and spelling
Germany finance in Englishfinance-de-enJurisdiction and source coverage
Medical Englishmedical-enRelevant terminology and pack readiness
curl --fail-with-body -sS 'https://api.adestool.com/v0/packs?active_only=true'

Discover installed packs at runtime instead of hard-coding a pack count. domain_hint, country_hint and retrieval_profile provide context where the request supports them; they do not create missing aliases or relationships. Only news analysis accepts country_hint directly.

Requests are JSON with Content-Type: application/json. The examples below work without an API key on the current hosted service. Edge security can reject some default HTTP client user agents. Use an identifiable client user agent, as shown in the Python example. A 403 is an access failure, not an empty extraction. Deployment-specific administrative routes may have additional restrictions.

Tag text

POST/v0/tag

text and pack are required. content_type defaults to text/plain. Optional fields include domain_hint, retrieval_profile, output and options.

entities contains direct matches. Each match includes its surface text, label, start/end offsets and optional linked identity, confidence, relevance and provenance. Keep the returned text alongside offsets; normalization and content processing matter when highlighting input.

related_entities, graph_support and impact_paths may be empty or null. Their presence depends on pipeline configuration. The options object accepts pipeline options, but the OpenAPI schema does not enumerate every supported key; consult the runtime's usage documentation before adding them.

Analyze news

POST/v0/news/analyze

Use the article text as the source of truth. Optional title, description, source, hints and country_hint carry context. packs selects requested libraries; automatic pack planning is enabled by default.

Request body · JSON 
{
  "text": "NVIDIA reported quarterly earnings.",
  "title": "NVIDIA quarterly earnings",
  "packs": ["finance-us-en"],
  "options": {
    "auto_pack_planning": false,
    "debug": true,
    "include_tag_responses": true,
    "include_impact_paths": true,
    "impact_max_depth": 2,
    "max_terminal_candidates": 16
  }
}

auto_pack_planning: false makes the chosen pack set explicit. Inspect packs_used and pack_decisions to see what actually ran. Diagnostic options help explain missing seeds, rejected candidates and absent terminal paths.

Verified with ADES 0.4.1: one source entity retaining mention_texts: ["NVIDIA"], zero terminal candidates, and event_incompatible / macro_gated reasons. Warnings report missing relationship-compatible and macro/FX/rates event signals. Extraction of a company name and a finance topic does not establish an earnings event's causal impact.

Expand impact paths

POST/v0/impact/expand

Supply canonical refs obtained from extraction or a trusted upstream resolver. This endpoint expands relationships; it does not accept article text or independently verify an event.

Request body · JSON 
{
  "entity_refs": ["finance-us-ticker:NVDA"],
  "language": "en",
  "enabled_packs": ["finance-us-en"],
  "max_depth": 2,
  "impact_expansion_seed_limit": 16,
  "max_candidates": 25,
  "include_passive_paths": true,
  "vector_proposals_enabled": false
}

max_depth accepts 1–4. The response includes source_entities, candidates, passive_paths, warnings and artifact identity. An extracted ref may still be missing from the relationship graph. An empty candidate list can correctly express a coverage gap. The example above returned NVDA, a broad US equity-market proxy and the US dollar at verification time. Those graph neighbors are not article-specific claims: news analysis retained the matched NVIDIA surface, then withheld candidates because the same short earnings sentence supplied no compatible event signal.

diagnostics, no_terminal_reasons, quality_flagsReasons to withhold or investigate output. Keep these visible in operational review.

Entity identifiers are not causal prose

Use entity_ref, terminal_ref or link.entity_id as the machine identity. Use the returned name, terminal_name or canonical_text as a display label. A label such as NVDA represents an entity; an arrow narrative such as “policy decision → financing cost → exposed sector” is prose, not an entity identifier.

For entity or asset chips, show only canonical entities extracted from the exact created or published article text. Keep the original identifier alongside its label. Do not split narrative chains into pseudo-entities or treat a formatted string as a canonical identity. Structured relationship_path.edges belongs in a separate evidence view. Derive both displayed entities and impact paths from that same article text; do not union entities or paths from research material, source stories or prior publications into the output. Those sources may substantiate prose, but their mentions are not mentions in the created article.

Matched surfaces and canonical names

ADES 0.4.1 adds optional ImpactSourceEntity.mention_texts, a list of matched input surfaces kept separately from the canonical name. For example, the article may say NVIDIA while the resolved name is NVDA. Retaining that surface allows impact grounding to check the actual mention without changing the canonical identity.

Clients should accept the additive field and treat an absent value as an empty list when reading older responses. Refs-only expansion has no article surface to supply, so it may return an empty list. This metadata preserves mention evidence; it does not establish event causality or turn every graph neighbor into a supported impact claim.

Optional fields can be null and arrays can be empty. Handle both explicitly. The current OpenAPI document is authoritative for nested field types and required properties.

Evidence & impact limitations

An impact path is a modeled relationship chain, not proof that this particular article causes a price move. Review the event, jurisdiction, source entities and each edge before presenting a candidate.

  1. Validate identity. Check canonical refs and distinguish a company, ticker, country and generic term.
  2. Validate the event. An article's wording, event signals and compatibility must support the proposed relationship.
  3. Validate provenance. Inspect source tiers, relationship path, effective dates, artifact identity and the weakest edge.
  4. Preserve abstention. Keep missing-terminal reasons, rejected candidates and coverage gaps. Do not synthesize an impact path from an empty output.

Confidence scores belong to pipeline decisions; they are not calibrated probabilities of market movement. Relationship proposals and vector neighbors need additional review before becoming trusted evidence. Some relationship source URLs identify local artifact files; a file:// reference is not a publicly retrievable citation. Retain artifact identity and obtain the underlying source evidence before publishing a source-linked claim.

Evaluate output quality

Separate operational failures from extraction and evidence failures. An HTTP 200, a green service status and a nonempty candidate list answer different questions.

CategoryWhat to measureWhat counts as a failure
OperationsAvailability, latency and validationTimeouts, 500s, inaccessible routes or invalid contracts
Extraction precisionSurface text, label and linked identityCommon words mistaken for people or companies, wrong tickers, duplicated misleading matches
Extraction coverageExpected supported entities and aliasesA known in-scope entity missing from the appropriate installed library
Relationship groundingExact published article text, canonical identity and matched surfacesA path retained without an anchored input entity, or a valid alias discarded because only its canonical ticker was checked
Impact evidenceEvent compatibility, source tiers, effective dates and weakest edgeGeneric graph proxies presented as article-specific market consequences
Correct abstentionEmpty results plus diagnosticsDo not classify emptiness alone as failure: out-of-scope text, absent evidence and rejected weak paths can correctly produce no output

Evaluate /v0/impact/expand as refs-only graph traversal. Evaluate /v0/news/analyze as text-grounded article analysis with additional filters. Broad country, currency and index neighbors from expansion are not automatically justified news terminals. For every positive example, include negative and ambiguous examples in regression review. For generated content, run analysis after the prose is finalized and store a text fingerprint with its extraction. When prose changes, reanalyze that text and retain the previous output as a revision rather than borrowing source-story metadata.

For a reproducible issue, save the exact input, endpoint, requested packs, packs_used, package/pack/artifact versions, warnings and expected behavior. Redact private content before sharing it.

Readiness & operations

curl --fail-with-body -sS --max-time 10 https://api.adestool.com/healthz
curl --fail-with-body -sS --max-time 30 https://api.adestool.com/v0/status
curl --fail-with-body -sS 'https://api.adestool.com/v0/packs?active_only=true'

/healthz checks service availability. /v0/status reports runtime status; pack listings show installed libraries. None alone guarantees accurate extraction or complete graph coverage.

Before upgrading a package or library, replay representative positive, negative and ambiguous examples. Compare canonical identities, false positives, abstentions and impact evidence. Keep package versions and artifact versions separately, and keep a rollback copy of the previous release.

Hosted usage limits and access depend on the deployment. These docs do not promise unlimited throughput or a service-level agreement. Prefer server-to-server calls; browser integrations require the operator's CORS policy to allow your origin.
